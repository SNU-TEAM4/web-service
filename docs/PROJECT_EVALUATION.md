주관적인 총점 대신 평가자가 직접 확인할 수 있는 결과를 남겼습니다. 현재 데이터는 공식 자료 기반 640행·10브랜드이며 자동 검증 결과 오류 0, 중복 0, 검증 행 640/640, 알레르기 확인 415/640, 원천·배포 CSV 해시 일치입니다. 웹에서는 이 품질 요약과 실제 한계를 함께 보여주고, 브랜드 비교를 네 가지 지표로 전환하며, Vercel Preview에서 같은 결과를 검증합니다.

## 1) 구조·내용 파악

- `vercel-app/components/HanipApp.tsx`: 메뉴 탐색, 조건 서랍, 장바구니, 지도, 브랜드 비교, 데이터 안내
- `scripts/update_official_data.py`: 브랜드 공식 자료 수집·정규화 후 두 CSV 동시 저장
- `scripts/validate_menu_data.py`: 필수 열, 수치 범위, HTTPS, ISO 날짜, 수집법, 중복, 알레르기 토큰, CSV 미러 해시 검사
- `vercel-app/public/data/quality.json`: 검증기의 공개 가능한 요약을 앱이 직접 읽는 계약
- `.github/workflows/quality.yml`: Python 테스트·검증, Next lint/build, 고위험 의존성 감사

핵심 사용자는 알레르기·영양 조건으로 메뉴를 안전하게 좁히고 공식 원문까지 확인하려는 방문자입니다. 발표자는 같은 화면에서 데이터 범위와 한계를 설명할 수 있어야 합니다.

## 2) 평가

### 데이터·주제

공식 출처와 데이터 계보는 강하지만, 기존 웹은 검증기의 결과를 보여주지 않았습니다. 또한 CSV 호환 필드 `fat`, `carbs`의 실제 공식 라벨 의미가 포화지방·당류라는 점을 프런트 모델에서 명확히 해야 했습니다. 알레르기 확인률도 브랜드마다 0~100%로 차이가 크므로 총합만 보여주면 안전성을 과장할 수 있었습니다.

### 시각화 완성도

기존 브랜드 비교는 필터를 통과한 메뉴 개수 한 가지뿐이었습니다. 평가자가 데이터 범위와 영양 차이를 탐색하기 어렵고, 지표의 표본·단위·정확값 연결도 약했습니다.

### 웹 구현·배포

Vercel용 반응형 구조는 있었지만 장바구니가 CSV 행 번호를 키로 사용해 데이터 재정렬 뒤 다른 메뉴를 가리킬 위험이 있었습니다. 조건 서랍 포커스 이동·복원, 탭 화살표 이동, 선택 칩 상태, 빈 결과 복구도 보완이 필요했습니다. 로고가 없는 새 브랜드의 매장 결과가 빈 이미지 경로를 받을 가능성도 있었습니다.

### AI 활용·발표

AI 보조 수집·코딩·QA의 사실보다 어떤 판단을 공식 원문과 사람이 검증했는지 보여주는 것이 중요합니다. 기존 화면에는 이 과정과 제한이 발표 흐름으로 정리되지 않았습니다.

## 3) 평가 기반 대안

1. 검증기의 요약을 공개 JSON으로 생성하고, 웹의 공식 출처 무대와 데이터 안내에서 PASS·오류·중복·해시 일치를 표시합니다.
2. CSV 스키마는 호환성을 유지하되 프런트 모델을 `saturatedFat`, `sugars`로 해석해 의미를 바로잡습니다.
3. 브랜드 비교는 서로 다른 단위를 섞지 않고 메뉴 수, 알레르기 확인률, 평균 단백질, 평균 나트륨 중 하나씩 전환합니다. 모든 차트에 0 기준·단위·표본·정확값 표를 붙입니다.
4. 장바구니 키를 `브랜드::메뉴명`으로 변경하고 저장 수화가 끝나기 전 빈 장바구니가 기존 값을 덮지 못하게 합니다.
5. Apple Korea에서 큰 제목·넓은 여백·절제된 파랑·흰 소개 무대와 검은 증거 무대의 대비만 참고하고, 서비스 고유 문구·데이터·컴포넌트로 구현합니다.
6. AI 활용 과정은 구조 파악 → 공식 자료 수집 → 자동 검증 → 사람의 Chrome 확인으로 설명합니다.

## 4) 대안 적용 결과

- 공개 품질 요약 생성: 640행, 10브랜드, 검증 640/640, 오류 0, 중복 0, 경고 1, CSV 미러 일치
- 경고 1건은 파리바게뜨가 공식 형식으로 확인된 1행뿐이라는 실제 범위 한계이며 화면에 숨기지 않음
- 스타벅스·써브웨이 알레르기 0%는 ‘없음’이 아니라 ‘미확인’으로 분리하고 알레르기 필터 선택 시 추천 제외
- 네 가지 비교 지표와 가로 막대, 0 기준, 툴팁 단위, 표본 수, 정확값 표 구현
- 안정 장바구니 키·저장 수화, 조건 초기화, 서랍 포커스 이동·복원, 탭 화살표/Home/End, `aria-pressed` 구현
- 메뉴·매장 로고 누락 시 이니셜 fallback 구현
- 실제 Chrome production build에서 필터 포커스 복원, 탭 키보드 이동, 장바구니 새로고침 유지, 비교 지표 전환 확인
- Chrome DevTools 모바일 에뮬레이션 390×844에서 `innerWidth=390`, `scrollWidth=390`으로 가로 오버플로 없음 확인
- Python 테스트, 데이터 검증, ESLint, Next production build 통과, npm 고위험 취약점 0건 확인
