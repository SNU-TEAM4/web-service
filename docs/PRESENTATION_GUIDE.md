# 발표 가이드: “예쁜 추천기”에서 “검증 가능한 추천기”로

## 5분 구성

1. **문제(40초)** — 프랜차이즈 영양·알레르기 정보가 흩어져 있고, 정보 미표기를 “안전”으로 오해하면 위험하다고 설명합니다.
2. **발견(60초)** — 개선 전 CSV의 단백질 549g·당류 1300g 행을 보여주고, 공식 롯데리아 표의 병합 셀 파싱 오류였음을 말합니다.
3. **해결(90초)** — 공식 출처 재수집, 날짜 의미와 수집 방식 기록, 이상치·중복·URL·두 CSV 해시 검사를 시연합니다.
4. **사용자 경험(70초)** — 15종 알레르기 중 “토마토” 선택 시 미표기 브랜드가 보수적으로 제외되는 것, 공식 원문과 기준일, 가로 비교 차트와 값 표를 보여줍니다.
5. **검증·한계(40초)** — 691행·11브랜드·오류 0·공식 기준가 51행, GitHub Actions·Vercel Preview 이력을 제시하되 알레르기 확인 470/691(68.02%), 파리바게뜨 1행, 카카오 키 미등록과 최신 배포 미검증을 함께 말합니다.

## AI 활용 공개 문구

> AI는 저장소 탐색, 결함 가설 수립, 검증 코드와 UI 대안 초안 작성에 사용했습니다. 공식 수치는 원문과 재수집 결과로 대조했고, Python 품질 게이트·Next.js 빌드·npm 감사·Chrome 사용자 여정으로 결과를 다시 검증했습니다. AI가 생성한 설명을 데이터 사실처럼 채택하지 않았습니다.

## 시연 순서

1. 공개 Streamlit URL이 실제로 열리는지 확인합니다.
2. 로컬 최신 Next.js에서 691개 메뉴·11개 브랜드·공식 기준가 51행과 최신 기준일을 확인합니다.
3. 대두 필터를 선택해 추천 수가 530개에서 106개로 줄어드는 것을 보여줍니다.
4. 데이터 안내에서 브랜드별 알레르기 확인율과 공식 원문을 보여줍니다.
5. 빠른 조건에서 `고단백 탐색`을 누르고 결과 수와 스포트라이트가 함께 바뀌는지, `다른 메뉴`와 `장바구니 담기`가 이어지는지 보여줍니다.
6. 브랜드 비교에서 중앙값 막대와 정확값 표를 확인한 뒤 `메뉴 분포`로 바꾸고 브랜드·메뉴를 선택해 칼로리×단백질 관계를 설명합니다.
7. 주변 매장 탭에서 키 없이 OpenStreetMap 미리보기가 보이고 GPS가 활성인지 보여줍니다. 키 설정 뒤에는 장소 검색 → 매장 목록 → 카카오 지도 핀 순으로 시연합니다.

## 예상 질문

- **오류 0이면 데이터가 완벽한가?** 아니요. 자동 검사는 구조와 명백한 이상을 검증합니다. 공식 원문의 의미와 제공량은 표본 수동 대조가 계속 필요합니다.
- **스타벅스 메뉴가 알레르기 선택 시 사라지는 이유는?** 수집 대상 공식 영양 페이지에서 메뉴별 알레르기 필드를 확인하지 못해 안전하다고 추정하지 않기 때문입니다.
- **왜 레이더를 없앴나?** 선택 메뉴에 따라 축 기준이 변하고, 나트륨이 높을수록 면적이 커져 좋은 값처럼 보일 수 있기 때문입니다.
- **실제 배포됐나?** Streamlit과 Vercel Production을 확인했고, 개선 브랜치도 Vercel Preview `Ready` 상태에서 실제 Chrome으로 열었습니다. 다만 2026-08-11 확인 시 카카오 REST·JavaScript 키가 아직 등록되지 않아 지도 성공 경로는 미검증입니다.
