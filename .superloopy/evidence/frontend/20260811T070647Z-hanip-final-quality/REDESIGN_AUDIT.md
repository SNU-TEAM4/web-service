# 한입안심 최종 프로젝트 리디자인 감사

## 범위

- 대상: 공개 Vercel Next.js 웹앱의 메뉴 탐색, 장바구니, 매장 검색, 비교, 데이터 안내
- 기준 화면: `baseline-desktop.png`
- 시각 기준: Apple Korea 홈의 큰 제목, 넉넉한 여백, 절제된 색, 흰 제품 무대와 검은 증거 무대의 대비만 차용한다. Apple 자산·문구는 복제하지 않는다.
- 사용 맥락: 방문자가 제한 시간 안에 자신의 알레르기·영양 조건에 맞는 메뉴를 안전하게 좁히고, 선택 근거를 확인하는 상황

## 평가 기준별 진단

### 1. 데이터·주제

- 강점: 공식 API·HTML·공식 이미지에서 수집한 640개 행, 원문 URL·기준일·수집법·알레르기 확인 여부가 행 단위로 보존되어 있다.
- 결함: CI 검증 결과가 앱 안에 드러나지 않아 발표자가 데이터 신뢰도를 별도로 설명해야 한다.
- 결함: CSV 필드 `fat`, `carbs`는 실제 의미가 포화지방·당류이므로 프런트 모델 명칭을 의미에 맞게 바꿔야 한다.
- 결함: 브랜드별 알레르기 확인률 차이가 핵심 제약인데 첫 화면에서는 총합만 보인다.

### 2. 시각화 완성도

- 강점: 현재 필터를 통과한 브랜드별 메뉴 수를 가로 막대로 표시한다.
- 결함: 단일 개수 지표만 있어 데이터의 품질과 영양 비교를 탐색할 수 없다.
- 결함: 차트 단위·표본 수·필터 기준과 정확값 표가 더 명시적으로 연결되어야 한다.

### 3. 웹 구현·배포

- 강점: Next.js/Vercel 공개 URL, CSV 오류 상태, 카카오 검색 오류 상태, 반응형 CSS가 존재한다.
- 결함: 장바구니 키가 CSV 행 번호라 데이터 갱신·정렬 시 다른 메뉴로 바뀔 수 있다.
- 결함: 조건 서랍의 포커스 이동·복원, 탭 키보드 이동, 토글 상태 노출이 부족하다.
- 결함: 로고가 없는 브랜드의 매장 검색 결과는 Next Image에 빈 경로가 전달될 수 있다.

### 4. AI 활용·발표

- 강점: 공식 소스 수집기, 검증기, CI, 브라우저 QA의 과정 증거가 저장되어 있다.
- 결함: 최종 웹페이지에서 구조 파악 → 수집·정제 → 검증 → 배포라는 AI 보조 과정을 설명하지 않는다.

## 리디자인 명제

“공식 라벨을 근거로, 조건을 바꾸며 확인하고, 정확값까지 설명할 수 있는 영양 탐색 실험실.”

정보 위계는 `약속 → 출처·검증 증거 → 현재 조건 → 메뉴/비교/장바구니 → 데이터·AI 과정`으로 고정한다.
